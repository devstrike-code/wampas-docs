01 — Phase 3 Flow Scope

Phase 3 introduces the complete Social layer: fellowship rooms, prayer rooms (live and async), direct messaging, elder governance, and the denomination HQ dashboard. All flows below are new additions to the system. Phase 1 and 2 flows remain active.

02 — Fellowship Room Lifecycle
1. Create Room
  • Account user taps 'Create Room' from Rooms section.
  • Form: room name, type (Cell Group / Bible Study / Topic / Denomination-wide / Open Fellowship), linked church (optional), privacy (open/invite-only), description.
  • Owner role assigned to creator. System creates room, indexes for search.
2. Join Room
  • Open room: tap Join → account confirmed → member added.
  • Invite-only room: user requests to join → owner/elder approves → member added.
  • Room linked to church profile: visible on church's Rooms tab → members discover via church profile.
3. Room Governance
  • Owner assigns up to 3 elders from existing members.
  • Elder actions: warn member (visible to member + owner), mute member (24h / 7d / permanent), remove member.
  • 3 warnings on same member → auto-escalation to owner review.
  • Owner can appeal elder decisions or overrule them.
  • Platform admin can supersede owner/elder for platform-level violations.
4. Room Posting
  • Text posts, archive message links (rendered as embedded cards), scripture references, image (single).
  • External links require elder approval before they display as links (shown as plain text until approved).
  • Post reporting: any member can flag a post. 3 flags → elder notified. Elder approves or removes.
03 — Prayer Room — Async Flow
1. Submit Prayer Request
  • User taps 'Post Prayer Request' in any Prayer Room.
  • Text (max 500 chars), anonymous toggle (hides display name, preserves account for moderation).
  • Anonymous requests: enters admin review before publishing (default 2-hour window).
  • Published request: visible to all room members.
2. Intercede
  • Member taps 'Standing in Agreement' — count increments, member added to intercessor list.
  • Member can post an intercession response: short prayer text under the request.
  • Intercessor list visible to request poster (encouragement signal).
3. Mark Answered
  • Request poster taps 'Mark as Answered'.
  • Prompted to write testimony (optional but encouraged).
  • Answered request: green badge, moved to Answered section of room.
  • Testimony entered into platform's answered prayer archive (discoverable globally).
04 — Prayer Room — Live Session Flow
1. Create Session
  • Verified pastor or room elder creates live session: title, duration (30/45/60/90 min), start time.
  • Session posted to room. Members notified via push notification.
  • Pastor-created sessions highlighted on pastor's profile and feed.
2. Run Session
  • Session starts at scheduled time. Leader posts session theme.
  • Structured turns: leader marks when it's open for member responses.
  • Members post prayers, scriptures, responses in real-time (WebSocket).
  • Leader can spotlight a member response (pinned for all to see).
3. End Session
  • Leader taps End Session or time expires.
  • Session transcript archived in room history.
  • Leader can publish a session summary to the public feed.
  • Participants notified with link to transcript.
05 — Direct Messaging Flow
1. Initiate DM
  • Account user visits another user's public profile.
  • Taps 'Send Message' (only visible if recipient has DMs enabled in settings).
  • Thread created. Message delivered in real-time via WebSocket.
2. DM Governance
  • DMs are end-to-end private but reportable.
  • Report DM: submits thread to admin review (admin can view reported thread).
  • Same escalation path as public content violations.
06 — Denomination HQ Dashboard Flow
1. Onboarding
  • Devstrike team signs licence agreement with denomination HQ.
  • Admin provisions HQ role on denomination's master account.
  • HQ account linked to all church profiles under that denomination.
2. Dashboard Capabilities
  • View all messages attributed to any church in the denomination, filterable by branch, pastor, category, date.
  • Flag a message for pastoral review — flagged message visible to church rep for response.
  • Analytics: message volume by branch, trending topics across denomination, reaction counts.
  • Export: CSV export of messages for any date range.
3. Branch Communication
  • HQ can publish a denomination-wide announcement to all branches' church profiles.
  • Announcement appears as a pinned notice on each branch's profile page.
  • Churches can acknowledge the announcement — acknowledgement count visible to HQ.
07 — Premium Subscription Flow
1. Upgrade to Premium
  • User taps 'Go Premium' from profile or feed.
  • Plan selection: Monthly ₦2,500 / Annual ₦25,000.
  • Paystack Subscriptions API handles recurring billing.
  • On activation: ad-free flag set, curated booklets unlocked, premium badge shown.
2. Premium Features Active
  • Ad-free browsing across feed, archive, events.
  • Monthly curated message booklet (PDF, generated by editorial team).
  • Premium badge on profile and in rooms.
  • Early access to new features before general release.
