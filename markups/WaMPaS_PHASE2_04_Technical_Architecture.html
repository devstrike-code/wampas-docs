01 — Phase 2 Architectural Additions

Phase 2 adds four new architectural components: a background job worker, a cache layer, Google Calendar OAuth, and the Paystack payments integration. The social feed is introduced as a standard REST API with no real-time requirement yet.

04 — Paystack Integration Architecture

All payments follow a strict three-step flow to ensure webhook reliability and prevent double-processing.

1. Initiate
  • Client calls POST /api/v1/payments/initiate with type, amount, metadata.
  • API creates a pending payment record in DB with Paystack reference.
  • API returns Paystack checkout URL. Client redirects.
2. Process
  • User completes payment on Paystack. Paystack fires webhook to /api/v1/payments/webhook.
  • API validates HMAC-SHA512 signature. Rejects if invalid.
  • API retrieves pending payment by reference. Updates status to 'success' or 'failed'.
3. Activate
  • On success: activates relevant feature (Sponsored badge, verified check, etc.).
  • Sends receipt email via Resend.
  • Idempotent: duplicate webhook fires are safely ignored (status already updated).
