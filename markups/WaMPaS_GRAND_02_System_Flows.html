01 — Flow Index

This document covers the complete user flow system across all three platform layers. Phase-specific flows are documented in Phase 1, 2, and 3 System Flow documents. This document covers the cross-layer flows and the full mature-state system.

02 — Authentication & Identity
1. Entry
  • User arrives at any page. System detects: authenticated account, guest, or new visitor.
  • Guest: full read access immediately. Post limit enforced by cookie + IP.
  • Account: full access based on role (user / elder / pastor / admin / hq).
2. Registration
  • Form: name, email, password, church (optional).
  • Email verification sent via Resend.
  • On verify: account activated, user redirected to feed with welcome banner.
3. Single Identity Across All Layers
  • One login spans Archive, Events, Feed, Fellowship Rooms, Prayer Rooms.
  • Role upgrades (elder, verified pastor) added to same account — no re-registration.
  • Account deletion: soft-delete. Content attributed to '[deleted user]' — archive integrity preserved.
03 — Archive Flows (All Phases)
1. Post Message
  • Guest KYC gate (name+email, cookie count check). Account: skip gate.
  • Form: message text (DM Serif preview), pastor typeahead, church, date, category, Bible ref, event (optional).
  • Submit → POST /api/v1/messages → success → message detail page + share prompt.
2. Message Detail Interactions
  • React (no account required). Share (native share sheet + quote card). Save (account only).
  • Q&A: one question per user. Pastor email notified if contact on file.
  • Report: reason picker → 3 same-category reports → poster notified → 5 total → admin queue.
3. Pastor / Church Profile Lifecycle
  • Created by account user. Mutable fields: any account user can edit.
  • Immutable fields (name, founding date): edit request goes to support.
  • Verified status: application + annual fee → admin approval → blue check displayed.
04 — Events Layer Flows
1. Concluded Event
  • Browse → view event → tabs: Messages / Pastors / Testimonies / Fellowship Room.
  • Submit testimony: KYC (guest) or account prefill → text → moderation queue → published.
  • Testimony marked 'Answered Prayer' by poster → enters answered prayer archive.
2. Upcoming Event + Sponsorship
  • Create event (account only) → form: name, church, dates, location, theme, pastors, image.
  • Ad subscription prompt: Tier A/B/C → Paystack checkout → on success → Sponsored badge activated.
  • Save to Calendar → Google Calendar OAuth → calendar event created via API.
05 — Social Layer Flows
1. Public Feed
  • Post: text, scripture, archive share, photo. All posts attributed — no anonymous posts.
  • Feed ranked: recency + reactions + followed pastors/churches.
  • React: Amen / Fire / Praying. Comment: threaded, flaggable. Share: native share.
2. Fellowship Room Lifecycle
  • Create room: name, type (cell/Bible study/topic/open), linked church (optional), privacy (open/invite).
  • Owner assigns up to 3 elders. Elders can warn → mute → remove members.
  • Post: text, archive links, scripture. No external links without elder approval.
  • Room linked to church profile: visible on church's Rooms tab.
3. Prayer Room — Async Mode
  • Post request: text, anonymous toggle (hides name, preserves account link for moderation).
  • Intercessors tap 'Standing in Agreement' — count visible on request.
  • Original poster marks request Answered → writes testimony → enters answered prayer archive.
  • Admin reviews anonymous requests before publishing if flagged.
4. Prayer Room — Live Mode
  • Verified pastor or elder creates session: title, duration (30–90 min), room.
  • Members join session. Leader posts prompts. Members respond in structured turns.
  • Session ends: transcript archived in room history. Highlighted on pastor's profile.
5. Direct Messaging
  • Account users can initiate DM with any user who has DMs enabled.
  • Messages governed by community standards — reportable, reviewable by admin.
  • Unacceptable content in DMs: same offence escalation as public content.
