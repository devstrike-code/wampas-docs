01 — Phase 2 Additional Flows

This document covers flows added or significantly modified in Phase 2. All Phase 1 flows remain active and unchanged. Phase 2 introduces: sponsored events, payment processing, calendar integration, verified profiles, PWA, public feed, and social interactions.

02 — Event Ad Subscription Flow
1. Create Sponsored Event
  • Account user creates upcoming event (Phase 1 flow).
  • After saving: 'Promote this event?' prompt with Tier A / B / C plan cards.
  • User selects tier → POST /api/v1/payments/initiate {type: 'event_ad', tier, event_id}.
  • Redirect to Paystack checkout. On success: Paystack webhook fires to /api/v1/payments/webhook.
  • Webhook validates HMAC signature → activates Sponsored badge on event for subscription duration.
2. Sponsored Event Display
  • Events with active ad subscription: gold border, 'Sponsored' label, surfaced first in upcoming events.
  • Ad expiry: system auto-removes Sponsored badge at end of subscription period.
  • Church rep notified 3 days before expiry with renewal prompt.
03 — Calendar Integration Flow
1. Save Event to Calendar
  • Account user taps 'Add to Calendar' on any upcoming event.
  • [Not Google-authorised] → system initiates Google Calendar OAuth flow.
  • [Authorised] → POST to Google Calendar API → event created with title, date, location, link.
  • [Guest] → 'Create a free account to save events to your calendar' prompt.
04 — Verified Profile Flow
1. Application
  • Account user visits pastor/church profile they created or manage.
  • Taps 'Apply for Verification' → form: full legal name, supporting links, reason.
  • Selects payment tier: ₦10,000/year (pastor) or ₦25,000/year (church) → Paystack.
  • On payment success: application enters admin review queue.
2. Admin Review
  • Admin verifies identity against supporting information.
  • Approved: blue check badge activated on profile. Applicant emailed.
  • Rejected: applicant emailed with reason. Payment refunded.
05 — Donation Flow
1. Initiate Donation
  • 'Support WaMPaS' button in footer and profile page.
  • Suggested amounts: ₦500 / ₦1,000 / ₦2,500 / ₦5,000 / Custom.
  • POST /api/v1/donations/initiate → Paystack checkout.
  • Success: receipt email sent, donor name added to supporters list (opt-in).
06 — Public Feed Flow
1. Post to Feed
  • Account only. Compose button in nav.
  • Post types: Text reflection | Scripture (with reference) | Archive message share | Photo (single image).
  • All posts attributed. No anonymous posting permitted.
  • Post submitted → feed entry created → shown to followers and in main feed.
2. Feed Browsing
  • Default feed: mix of following + recent + trending.
  • 'Following' tab: only posts from followed pastors, churches, users.
  • React: Amen / Fire / Praying (one per user per post).
  • Comment: threaded. Flag button on every comment.
3. Archive-to-Feed Share
  • User taps Share → Post to Feed from any message detail page.
  • Feed post pre-populated: quote card image + pastor attribution + link to archive page.
  • User can add personal reflection text before posting.
07 — PWA Flow
1. Install Prompt
  • After 3rd visit or after first message post: browser install prompt shown.
  • Accept → app added to home screen with WaMPaS icon.
  • Service worker caches: feed page, pastor profiles browsed, saved messages.
  • Push notification permission requested on install.
2. Push Notifications
  • Event reminder: 24 hours before saved upcoming event.
  • 'Your pastor posted a new message' (if following a pastor).
  • 'Your question was answered'.
  • All notifications link directly to relevant content.
