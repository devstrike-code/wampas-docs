01 — Phase 1 Flow Scope

Phase 1 flows cover only the Archive layer and core Events (concluded + basic upcoming). Social layer flows do not exist in Phase 1. This document is the complete reference for Phase 1 frontend routing, API design, and QA test cases.

02 — Guest vs Account Decision Tree
1. Visitor Arrives
  • System checks for auth cookie.
  • [Authenticated] → account user flow.
  • [No auth] → guest user flow. Cookie checked for prior post count.
2. Guest Capabilities
  • Read all messages, pastor profiles, church profiles, events.
  • React to messages once per message.
  • Post up to 3 messages (cookie + IP enforcement).
  • Ask one question per message (inline KYC: name + email).
  • Share any message or event.
3. Account Capabilities
  • All guest capabilities, plus:
  • Unlimited message posting, create pastor/church/event profiles, edit mutable fields.
  • Save messages and events, suggest features.
03 — Message Posting (Primary Flow)
1. Entry Points
  • Gold FAB button on feed.
  • Add Message button on pastor profile.
  • Add Message button on church profile.
2. Guest KYC Gate
  • [Guest] Check cookie post count.
  • Count >= 3: show 'Limit reached — create a free account' modal.
  • Count < 3: show inline name + email fields before form.
3. Message Form
  • Message text (multiline, 2000 char max, live counter).
  • Pastor name: typeahead. If not found → option to create new pastor (account only).
  • Church: typeahead. Branch field appears if church has multiple branches.
  • Date preached: date picker, defaults to today.
  • Category: multi-select chips, max 3.
  • Bible reference: optional free-text.
  • Event: optional typeahead.
4. Submission
  • Client-side Zod validation → POST /api/v1/messages.
  • Success → message detail page opens + share prompt displayed.
  • Share sheet: WhatsApp (default), Instagram, Copy Image, Copy Link.
04 — Message Detail Flow
1. Load
  • Full message text, pastor, church, event, date, category, Bible ref.
  • Reaction counts. Q&A thread below.
2. Interactions
  • [React] → record, animate count.
  • [Share] → native share sheet + quote card image.
  • [Save] → account only → personal library.
  • [Question] → one per user, KYC or account prefill.
  • [Report] → reason picker → flag system.
05 — Pastor & Church Profile Flows
1. Browse
  • Searchable paginated list. Filter by church, denomination, most messages.
2. View Profile
  • Name, title, church, image, bio, contact, stats.
  • Tabs: Messages | Events | About.
3. Edit Logic
  • Mutable field: account user sees edit icon → inline edit → save.
  • Immutable field: 'Contact support to edit this field' → email to support team.
4. Create Pastor / Church
  • Account only. Form → save → linked to church if provided → creator set as original owner.
06 — Events (Phase 1 Scope)
1. Concluded Events
  • Browse → filter by church, pastor, year.
  • View event: messages, pastors, testimonies tabs.
  • Submit testimony: KYC or account → text → moderation → published.
2. Upcoming Events (Basic)
  • Account creates event: name, church, dates, location, theme, pastors, image.
  • No payment in Phase 1 — all upcoming events are free listings.
  • Listed chronologically on Events page.
07 — Search Flow
1. Entry
  • Search icon in nav. Bar auto-focused. Trending topics as chips. Recent searches for account users.
2. Execution
  • GET /api/v1/search?q=... after 300ms debounce.
  • Tabs: Messages | Pastors | Churches. Default: Messages.
3. Results
  • Tap result → detail page.
  • Zero results: 'No results for X — try a different spelling or browse by category.'
